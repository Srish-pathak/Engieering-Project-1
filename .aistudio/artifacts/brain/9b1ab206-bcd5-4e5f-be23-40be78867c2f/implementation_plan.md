# CodeLens AI — Static-Analysis-Grounded Multi-Agent Code Review & Documentation Platform

**Submitted by:** Srishti Pathak · Integrated M.Tech in Computer Science & Engineering · Central University of Jharkhand (2026)

CodeLens AI combines deterministic Python AST program analysis, static-analysis rules, and software metrics with a coordinated 6-agent Gemini AI review swarm, a Review Synthesizer, an Automated Documentation Generator, an Architecture Explorer, SQLite persistence, and an Experimental Evaluation framework (Approach A vs. Approach B vs. Approach C).

---

## Requirements Traceability Matrix (Audit of Existing `TecSpace Analyser` vs. `CodeLens AI` Synopsis)

| Requirement | Existing Status | Missing Work Identified in Audit | CodeLens AI Implementation |
| :--- | :--- | :--- | :--- |
| **1. Source Input Manager (Paste, File Upload, Project ZIP)** | **Partially implemented** (`app.py` supports Paste and single-file upload only) | No `.zip` archive parser, no path-traversal (`..`) validation, no ignored-folder filtering (`.venv`, `node_modules`, `__pycache__`), no multi-file inventory. | Full 3-mode Input Manager supporting Paste, Single File (`.py`, `.cpp`, `.java`), and multi-file Project `.zip` Upload (plus 1-click sample ZIP generator) with strict ZIP path-traversal protection and file limits. |
| **2. AST Structural & Docstring Extractor** | **Partially implemented** (`static_analysis.py` walks AST for bug rules only) | Does not extract full structural inventory (classes, methods, parameter type annotations, return types, call graphs, control-flow counts, or module/class/function docstring coverage). | Complete AST Structural Extractor in `backend/codelens_engine.py` extracting functions, classes, arguments, return types, docstrings, imports, internal calls, branch/loop/exception counts, and exact docstring coverage %. |
| **3. Deterministic Static Analysis Engine** | **Already implemented & tested** (13 Python AST rules + C++/Java rules in `static_analysis.py`) | Missing security-specific deterministic rules (`hardcoded-secret`, `sql-injection-risk`, `subprocess-shell-true`, `unsafe-deserialization`) and multi-file path attribution. | Preserves all 13 existing Python rules + C++/Java rules and adds deterministic security pattern detectors with file path, line number, code snippet evidence, and rule IDs. |
| **4. Software Metrics Engine (Cyclomatic Complexity & MI)** | **Already implemented & tested** (`complexity.py` uses `radon` & `lizard`) | Needs zero-dependency AST McCabe Cyclomatic Complexity ($M = E - N + 2P$) + Halstead/Radon Maintainability Index fallback when `radon` binary is absent, plus average function length and doc coverage metrics. | Uses `radon` when installed and provides an exact built-in Python `ast`/`tokenize` McCabe CC + Halstead MI calculator so `MEASURED` metrics work in every environment. |
| **5. 6-Agent Multi-Agent Review System & Orchestrator** | **Not implemented** (`reviewer.py` makes a single monolithic LLM call) | Existing project lacks specialized agents (`Code Quality`, `Simplification`, `Security`, `Complexity`, `Type/API Design`, `Documentation`), role-specific evidence routing, and per-agent telemetry. | Implements the **Review Orchestrator** dispatching AST facts, complexity metrics, and static findings to 6 distinct specialized Gemini agents with structured JSON schemas and single-agent/offline fallback. |
| **6. Review Synthesizer** | **Partially implemented** (`utils.merge_bugs` deduplicates static + single-AI bugs) | Does not merge across 6 specialized agents, does not separate deterministic facts from AI interpretations with verification status, or resolve cross-agent priorities. | Full **Review Synthesizer** that deduplicates multi-agent findings, preserves file/line/rule evidence, separates confirmed deterministic findings from AI suggestions, and validates improved code. |
| **7. Automated Documentation Generator** | **Not implemented** | Existing project only outputs bug cards and a short summary; no docstring generator, module/class/function docs, or `README.md` generator. | First-class Documentation Generator producing PEP-257 docstrings for undocumented functions/classes, module reference tables, architecture narrative, and downloadable `README.md`. |
| **8. 6-Page Engineering UI + Architecture Explorer** | **Partially implemented** (Streamlit single-page tabs) | Needs React + TypeScript + Tailwind dark/light engineering workbench with dedicated pages for *Overview*, *Code Review*, *Complexity*, *Security*, *Documentation*, and *Architecture Explorer*. | Complete React + Vite + Tailwind + Recharts interface with all 6 core views plus the *Experimental Evaluation & Viva Guide* module. |
| **9. SQLite Persistence & Report Exports** | **Partially implemented** (`utils.py` uses `review_history.json`; `report.py` exports `.md`, `.html`, `.json`) | Synopsis specifies relational persistence for `Project`, `SourceFile`, `ReviewRun`, `Finding`, `AgentResult`, and `GeneratedDocument`. | Implements modular SQLite persistence (`backend/codelens.db` via Python `sqlite3`) alongside downloadable Markdown, HTML, and JSON reports. |
| **10. Experimental Evaluation (Approach A vs. B vs. C)** | **Not implemented** | Synopsis Section 18 requires quantitative comparison of *Approach A (Direct Single-LLM)*, *Approach B (Multi-Agent without Static Grounding)*, and *Approach C (Static-Analysis-Grounded Multi-Agent)* using ground-truth annotated samples (Precision, Recall, F1, FP rate, Latency, Doc Coverage). | Implements the interactive **Experimental Evaluation Engine** with ground-truth annotated benchmark datasets and real-time calculation of Precision, Recall, F1 Score, False Positives, Known-Issue Coverage, and Doc Coverage delta. |
